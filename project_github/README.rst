This module imports the issues of a GitHub repository as tasks of a
project, and keeps them up to date with a scheduled job. It does not
need the Helpdesk modules.

A project is linked to one GitHub repository. Every issue becomes a task
of that project and is updated on later runs. Pull requests are skipped.

+-----------------------+---------------------------------------------+
| GitHub                | Project task                                |
+=======================+=============================================+
| Title                 | Title                                       |
+-----------------------+---------------------------------------------+
| Body                  | Description (plain text)                    |
+-----------------------+---------------------------------------------+
| Labels                | Tags (reused by name, created when missing) |
+-----------------------+---------------------------------------------+
| Assignees             | Assignees: every assignee whose GitHub      |
|                       | Login matches an internal user              |
+-----------------------+---------------------------------------------+
| Closed as completed   | State *Done*                                |
+-----------------------+---------------------------------------------+
| Closed as not planned | State *Cancelled*                           |
+-----------------------+---------------------------------------------+
| Reopened              | State *In Progress*                         |
+-----------------------+---------------------------------------------+
| Number, URL, state    | Read-only GitHub tab on the task            |
+-----------------------+---------------------------------------------+

New tasks start in the project's first stage, and the sync never moves
tasks between stages, so you can use the stages as you like. GitHub is
the source of truth for the title, description, tags and assignees:
changes made in Odoo are overwritten the next time the issue changes on
GitHub. Creating tasks does not notify the assignees.

Installation
============

To install this module, you need to:

1. Clone this repository and add the repository folder to the Odoo
   ``addons_path``. Each module is a folder of the repository, and this
   module needs ``github_issue_sync`` from the same repository.
2. Install the Python dependency: ``pip install requests``.
3. Update the apps list and install *Project GitHub Sync*.

Configuration
=============

To configure this module, you need to:

1. Set the GitHub access token and, optionally, the *GitHub Login* of
   your users. Both come from the *GitHub Issue Sync*
   (``github_issue_sync``) module: see its configuration section. The
   token is in *Settings > General Settings > Integrations*.

Usage
=====

To link a project to a repository:

1. Open a project (*Project > Projects*, then the project's settings).
   You must be a Project administrator.

2. Open the *GitHub* tab, enter the repository as ``owner/name`` and
   tick *Sync with GitHub*.

   .. image:: https://raw.githubusercontent.com/lloydvheremu/helpdesk_mgmt_github/main/project_github/static/description/usage_project_github_tab.png
      :alt: GitHub tab of the project

3. Click *Sync now*, or wait for the hourly scheduled action *Project:
   Sync GitHub issues*. A notification shows how many tasks were created
   and updated.

4. The issues are now tasks of the project, with their labels as tags.
   Here all the issues of the repository are closed, so every task is
   *Done*:

   .. image:: https://raw.githubusercontent.com/lloydvheremu/helpdesk_mgmt_github/main/project_github/static/description/usage_project_tasks.png
      :alt: Imported tasks

5. Open a task and use its *GitHub* tab to see the issue number, a link
   to the issue, its state and the time of the last sync. Issue 7 is
   assigned to the GitHub account set as the *GitHub Login* of the
   Administrator:

   .. image:: https://raw.githubusercontent.com/lloydvheremu/helpdesk_mgmt_github/main/project_github/static/description/usage_task_github_tab.png
      :alt: GitHub tab of the task

Running the sync again never creates duplicates, even if a task was
archived. If GitHub returns an error (bad token, rate limit, repository
not found, timeout), it is posted in the project's chatter and the last
sync time is not advanced, so the next run fetches the same issues
again.

Development
===========

Run the tests on a throwaway database. They mock GitHub, so they work
offline:

.. code:: sh

   odoo-bin -d test_project_github -i project_github --test-tags /github_issue_sync,/project_github --stop-after-init

Known issues / Roadmap
======================

-  Choose a stage for closed issues, as the Helpdesk module does.
-  Send changes made in Odoo back to GitHub (two-way sync, planned for
   v2).
-  Webhooks, so updates arrive immediately instead of with the next run.
-  Render the Markdown of issue bodies and import issue comments.
-  Sync GitHub Projects boards (GraphQL API).
